## Задание

Требуется создать «помощник» (инструмент) для проверки выражений, используемых в
приложениях, на регулярность:

- пользователь вводит произвольное выражение (не обязательно регулярное);
- пользователь вводит произвольную строку (регулярное выражение не обязательно
  содержится в ней);
- по нажатию кнопки выполняется проверка на регулярность;
- если выражение нерегулярное — выдаётся предупреждающее сообщение;
- если строка пустая — выдаётся предупреждающее сообщение;
- если выражение содержится в строке — совпадение выделяется;
- если не содержится — выдаётся сообщение об отсутствии.

Дополнительное условие из задания: **избегать использования regex-библиотек**.
Поэтому в проекте нет `System.Text.RegularExpressions`: парсер, построение автомата
и поиск написаны вручную.

## Что сделано

Приложение на C# (Windows Forms, .NET 8) с собственным regex-движком:

- ввод выражения и строки;
- проверка синтаксиса выражения;
- проверка именно **регулярности** (обратные ссылки, lookaround, условия и рекурсия
  отвергаются как нерегулярные конструкции);
- предупреждение о пустой строке;
- поиск всех неперекрывающихся совпадений;
- подсветка найденных фрагментов жёлтым цветом;
- список совпадений с позицией, длиной и фрагментом;
- вкладка «Разбор выражения» с деревом разбора и количеством состояний NFA;
- вкладка «Справка» с поддерживаемым синтаксисом;
- мини-справка по синтаксису прямо на главном экране — под строкой поиска,
  чтобы составлять выражение, не переключаясь на другую вкладку;
- набор готовых примеров, включая нерегулярные выражения и ошибки синтаксиса;
- флажок «Игнорировать регистр»;
- защитные лимиты от зависания и переполнения стека.

## Как устроено

### 1. Парсер

`RegexParser` — рекурсивный парсер с грамматикой:

```
alternation := concat ('|' concat)*
concat      := (atom quantifier?)*
atom        := literal | '.' | '^' | '$' | class | group | escape
quantifier  := '*' | '+' | '?' | '{n}' | '{n,}' | '{n,m}' ('?' для ленивости)
```

На выходе получается дерево из узлов `RegexNode`:

- `LiteralNode`, `AnyCharNode`, `CharClassNode`;
- `ConcatNode`, `AlternationNode`, `RepeatNode`, `GroupNode`;
- `AnchorNode` (`^`, `$`, `\b`, `\B`, `\A`, `\z`, `\Z`);
- `EmptyNode` для пустых ветвей.

Парсер сразу определяет категорию ошибки:

- `Syntax` — выражение синтаксически некорректно;
- `NotRegular` — выражение корректно для «больших» regex-движков, но не является
  регулярным (обратные ссылки, lookaround, условия, рекурсия, балансирующие группы);
- `Unsupported` — конструкция регулярна, но учебный движок её не поддерживает
  (атомарные группы, possessive-квантификаторы, встроенные флаги `(?i)` и т. п.).

Именно поэтому инструмент умеет отличать «нерегулярное выражение» от «ошибки
синтаксиса» и от «неподдерживаемой, но регулярной конструкции».

### 2. NFA

Дерево компилируется в недетерминированный конечный автомат по методу Томпсона:

- литерал/класс — состояние с переходом по символу;
- конкатенация — последовательное соединение с ε-переходами;
- альтернатива — ε-ветвление;
- `*`, `+`, `?`, `{n,m}` — обязательные копии и циклы/необязательные копии.

Якоря и границы слова — это ε-переходы с проверкой условия в текущей позиции.
Состояний не больше 50 000; при превышении выдаётся понятная ошибка.

### 3. Поиск

Поиск выполняется эмуляцией NFA «в ширину». На каждом шаге хранится множество
достижимых состояний и самое левое начало совпадения для каждого состояния.
Это даёт:

- **левое-длинное** совпадение (leftmost-longest);
- отсутствие катастрофического backtracking;
- отсутствие рекурсии по длине строки, поэтому нет переполнения стека;
- защиту по количеству шагов (5 000 000).

После найденного совпадения поиск продолжается с его конца, поэтому совпадения
не перекрываются.

### 4. Подсветка

Найденные фрагменты копируются в отдельное поле `RichTextBox`, где для каждого
непустого совпадения задаётся `SelectionBackColor` (жёлтый). Список совпадений
показывает позицию (с 1), длину и фрагмент. Пустые совпадения (например, `a*` на
`bbb`) отображаются как `(пусто)` — подсвечивать в тексте нечего.

## Поддерживаемый синтаксис

| Конструкция | Пример |
|---|---|
| Литералы | `abc` |
| Любой символ, кроме `\n` | `.` |
| Классы | `[abc]`, `[^abc]`, `[a-z]`, `[А-Яа-яЁё]` |
| Сокращения | `\d \D \w \W \s \S` |
| Unicode-категории | `\p{L}`, `\p{Lu}`, `\p{Nd}`, `\P{L}` |
| Квантификаторы | `* + ? {n} {n,} {n,m}` |
| Ленивые квантификаторы | `*? +? ?? {n,m}?` |
| Группы | `(...)`, `(?:...)`, `(?<имя>...)`, `(?'имя'...)` |
| Альтернатива | `cat` или `dog` |
| Якоря | `^ $ \A \z \Z \b \B` |
| Escape | `\n \r \t \f \v \0 \a \e \x41 \u0410 \cA` |
| Экранирование метасимволов | `\. \* \+ \? \( \) \[ \] \{ \} \| \\ \^ \$ \- \/` |

Ленивые квантификаторы принимаются синтаксически, но движок всё равно ищет
самое длинное совпадение в самой левой позиции. Это явно написано в справке.

## Примеры для демонстрации

| Что показать | Выражение | Строка |
|---|---|---|
| E-mail | `\b[\w.+-]+@[\w-]+\.[\w.-]+\b` | `sstat@grsu.by, support@example.com` |
| Телефон | `\d{3}-\d{2}-\d{3}` | `Телефон: 123-45-678` |
| Русские слова | `[А-Яа-яЁё]+` | `Съешь ещё этих мягких французских булок.` |
| Дата | `\d{2}\.\d{2}\.\d{4}` | `05.10.2026` |
| URL | `https?://[^\s]+` | `https://grsu.by` |
| Unicode | `\p{Lu}+` | `ABC def ПРИВЕТ` |
| Нерегулярное | `(a)\1` | `aa` |
| Lookahead | `foo(?=bar)` | `foobar` |
| Ошибка синтаксиса | `[a-z` | `abc` |
| Пустая строка | `a+` | *(пусто)* |

Все они есть в выпадающем списке «Пример» в приложении.

## Ограничения

- длина строки — до 20 000 символов;
- длина выражения — до 100 000 символов;
- вложенность групп — до 500;
- состояний NFA — до 50 000;
- шагов поиска — до 5 000 000;
- показывается до 2 000 совпадений;
- `^` и `$` работают для всего текста, а не для каждой строки (многострочный
  режим не включён);
- `.` не соответствует `\n`;
- встроенные флаги `(?i)`, `(?m)`, `(?s)` не поддерживаются — для регистра есть
  отдельный флажок;
- `\w` и `\b` используют упрощённое определение слова:
  буквы/цифры Unicode и `_`;
- Unicode-категории работают в пределах BMP (тип `char`).

## Коротко для защиты

1. **Почему это не обычный regex?** Используется собственный парсер и NFA;
   в исходниках движка нет `System.Text.RegularExpressions`.
2. **Что значит «проверка на регулярность»?** Сначала проверяется синтаксис, затем —
   не использует ли выражение конструкции, которые выводят язык за пределы
   регулярных: обратные ссылки, lookaround, условия, рекурсию, балансирующие группы.
3. **Почему `(a)\1` нерегулярно?** В общем случае обратная ссылка требует
   запоминать произвольную длину предыдущей группы, а конечный автомат не имеет
   памяти такого вида. Конкретное `(a)\1` случайно описывает конечный язык,
   но мы консервативно отвергаем саму нерегулярную конструкцию.
4. **Почему NFA, а не рекурсивный backtracking?** NFA не переполняет стек и не
   зависает на патологических выражениях; сложность ограничена числом состояний.
5. **Как выделяются совпадения?** Движок возвращает позицию и длину, интерфейс
   копирует строку в `RichTextBox` и задаёт жёлтый фон для каждого фрагмента.
6. **Что с пустыми совпадениями?** Они показываются в списке как `(пусто)`, но не
   подсвечиваются; поиск принудительно сдвигается на символ вправо, чтобы не
   зациклиться.
